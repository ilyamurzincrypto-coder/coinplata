## WW-135 (kit out) висит на неактивном офисе

**Заведено:** 2026-08-27, при подготовке Экрана 4 «Счета · Крипто».
**Статус:** открыта. В PR Экрана 4 НЕ чинится по прямому указанию владельца —
там только презентационный слой.

**Что видно в UI:** кошелёк попадает в группу «Без офиса» с пометкой
«кошелёк не привязан», $21 497,36 он-чейн.

**Что на самом деле в данных** (`public.accounts`, прод, проверено SQL):

| поле | значение |
|---|---|
| id | `0fb6b363-dec9-47a4-89ff-c77b2ca3ca99` |
| name | WW-135 (kit out) |
| network / currency | TRC20 / USDT |
| address | `TYtC1HoczFTciw1Pp6c5m2vR6by8W1j9nd` |
| office_id | `63edef46-a114-4c98-9a38-497864ca1900` |
| aegis_wallet_id | `cmrx8r0ol0kok6mx5xdq8ndgn` |
| active | true |

То есть **`office_id` не пустой**. Формулировка «кошелёк не привязан» неточна:
он привязан к офису `63edef46…` = **«International Office» (city Worldwide)**,
у которого `active = false` и `coinpoint_office_code = null`. UI строит группы
по активным офисам, неактивный в список не попадает — и кошелёк проваливается
в «Без офиса».

**Значит решений два, и это выбор владельца, а не разработчика:**

1. Перепривязать кошелёк к реальному офису (какому — знает владелец), либо
2. Активировать «International Office» как легитимный контейнер для
   кошельков вне городов и показывать его группой наравне с остальными.

Пока не решено — группа «Без офиса» в ведомости остаётся честным отражением
того, что офис кошелька не входит в активный список. Данные не трогаем.

**Связано:** оранжевая пометка «кошелёк не привязан» в Экране 4 эталона.
Если выбрать вариант 2, текст пометки надо будет поменять — сейчас он
утверждает то, чего в данных нет.
