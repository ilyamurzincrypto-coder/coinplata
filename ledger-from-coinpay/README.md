# Леджер CoinPay → CoinPlata

Комплект передачи от 14.10.2026. Три части: правила, ядро кодом, вид.

Передаётся не «как у нас сделано», а **что обязано быть верно**. Реализация у вас своя — леджер
CoinPlata живёт функциями Postgres (`ledger.*` RPC), и это разумный выбор для вашего стека.
Переносить архитектуру не нужно; переносить нужно канон и вид.

---

## Чем отличаются проекты (чтобы не ждать невозможного)

| | CoinPay | CoinPlata |
|---|---|---|
| Стек | Next 15 (App Router) + Drizzle + Neon | Vite + React 18 + Supabase |
| Где логика леджера | TypeScript (`packages/core`) | функции Postgres `ledger.*` |
| Типы | TypeScript strict | **JavaScript** (277 `.jsx`, TS нет) |
| Стили | Tailwind + CSS-переменные | **Tailwind есть** ✅ |

Два следствия, важных сразу:

1. **Tailwind у вас есть** — значит разметка и токены переносятся один в один, без переписывания
   стилей.
2. **TypeScript у вас нет.** Vite соберёт `.ts` через esbuild, то есть код **заработает**. Но без
   `tsconfig` не будет проверки типов — а в денежном коде типы и есть защита: они не дают сложить
   `bigint` с `number` и перепутать минорные единицы с мажорными. Рекомендация: включить TS хотя бы
   для папки `core/` (`checkJs` не нужен, остальной проект не трогается). Если не включать —
   считайте, что половина пользы ядра осталась здесь.

## 1. Правила — `CANON.md`

12 правил, каждое с инцидентом, который его оплатил. Читать первым. Переносится на любой стек,
включая ваши функции Postgres.

Самое важное, если читать нечего, кроме одной строки:
**Σ=0 НЕ ловит ошибку масштаба** — обе ноги проводки бывают неверны одинаково. Поэтому в каждом
денежном тесте обязан быть четырёхзначный случай.

## 2. Ядро — `core/`

Чистый TypeScript: 56 модулей + **64 файла тестов**. Зависимости — только `zod`.

### Проверено прямо здесь, в вашем проекте

Я запустил тесты ядра вашим `vitest` и починил то, что всплыло:

- 🔴 `tsconfig.json` ядра наследовался от корневого конфига CoinPay, которого у вас нет —
  тесты не запускались ВООБЩЕ (`TSCONFIG_ERROR`). В комплекте лежит самодостаточный конфиг.
- ⚠️ **Нужен `zod`:** `npm i zod`. Его требует ровно ОДИН модуль — `currencies.ts`. Все денежные
  модули (`money`, `ledger`, `postings`, `chain-amount`, `account-number`, `statement`, `fx`) от
  него не зависят и работают без установки.

После `npm i zod`:
```
npx vitest run ledger-from-coinpay/core/src
```

```
core/src/money.ts            минорные единицы, арифметика
core/src/ledger.ts           проводки, Σ=0 по транзакции и валюте
core/src/postings.ts         сборка ног операций
core/src/account-number.ts   нумерация 1xx–4xx
core/src/chain-amount.ts     знаки сети ↔ знаки книги (6/18 vs 4)
core/src/fx.ts, rates.ts     курсы, кросс-курсы
core/src/statement.ts        выписка и running balance
```

⚠️ **Три модуля тянут `node:crypto` и в браузере НЕ заработают:** `totp.ts`,
`secret-cipher.ts`, `two-factor-policy.ts`. Это охранный контур, к деньгам отношения не имеет —
используйте их на сервере (Supabase Edge Functions) или не берите вовсе. **Весь денежный контур
браузеро-безопасен.**

🔴 **Тесты переносите ПЕРВЫМИ.** Они точнее любого текста описывают правила: 64 файла — это
формальная запись канона. Если переписываете леджер на Postgres-функциях, тесты становятся
приёмочным набором для RPC.

## 3. Вид — `view/` и `SCREENS.md`

`SCREENS.md` — опись экранов: заголовки, колонки в точном порядке, что показывает каждая, пустые
состояния, инварианты.

Компоненты разделены по переносимости:

**Переносятся как есть** (чистый React + Tailwind):
- `view/ui/Money.tsx`, `Amount.tsx`, `Payout.tsx` — форматирование денег
- `view/ui/StatusChip.tsx` — статус = цвет + СЛОВО (никогда только цвет)
- `view/finance/CurrencyBalances.tsx`

**Требуют переписывания слоя данных** (серверные компоненты Next, читают Drizzle):
- `view/finance/AccountsTable.tsx`, `AccountsList.tsx`, `FundsPanel.tsx`

Разметку и классы из них берите целиком — переписать нужно только то, откуда приходят данные.

`view/tokens.css` — дизайн-токены (цвета, типографика). Денежные величины: вес 600,
`tabular-nums`, **копейки того же кегля, что целая часть** — это отдельное требование владельца,
мелкие копейки нечитаемы.

## Чего в комплекте НЕТ и почему

- **Миграций базы.** У вас свои таблицы и свои RPC. Переносить нашу схему — значит ломать
  работающее. Берите из канона правила (Σ=0 триггером, журнал неизменяем триггером), а таблицы
  стройте под себя.
- **Серверных трактов проведения** (`apps/web/src/lib/finance/*`). Они написаны под Drizzle и
  серверные экшены Next. Их эквивалент у вас уже есть — `ledger.*` RPC.
- **Аутентификации и прав.** Другая модель, переносить нечего.
